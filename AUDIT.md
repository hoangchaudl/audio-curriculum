# StoryCo Audio Training Program: LMS Audit

_Read-only audit of branch `claude/storeyco-lms-audit-251f96` @ `b4df90e`, 2026-09-25. No code was changed._

**What I ran:** `tsc --noEmit` (passes), `vitest run src` (65/65 pass), `vite build` (passes), `npm audit`, `npm outdated`. I read the Firestore rules, auth/store layer, scoring and outline logic, the review queue, and the trainee/admin screens. I did **not** run the rules emulator suite (`npm run test:rules`), and I didn't look at the live Firebase project.

**Assumptions from your answers:** accounts should be **invite-only**, cohorts are **under 20 trainees**, and I read the brief literally: trainees get **continue/release decisions at weekly milestones**. I left the skill matrix and career tracks out, as you asked.

---

## Executive summary

The codebase is in better shape than most apps built this quickly. The Firestore rules deny by default, scope data per role and have tests. Submissions can only be added to, never edited. Reviewers score on their own and can't see each other's scores. The review flow for the 1–5 rubric is well modelled. Most of what's left falls into three groups. **First, the front door is open.** Anyone with the URL can create a trainee account, and an invite can be claimed by whoever signs up first with that email, because email ownership is never checked. There is also no way to remove a released trainee's access. These three findings (all High) are fixable in about one small PR, mostly in the rules. **Second, the product model stops short of the brief.** There is only one end-of-program "offer / no offer" decision, with no continue/release call at each weekly milestone. Milestones mark themselves "done" once their date passes. Changing weights or criteria in the middle of a cohort silently re-scores everyone, including trainees who have already been decided on. **Third, several small correctness and UX gaps** affect grading trust: the pass-benchmark label is hard-coded to 3.5, the benchmark field accepts a blank value (which saves 0, so everyone passes), Episode A reviews save as several separate writes that can half-fail, many failed saves show no error, and there is no "next review" flow. Performance and cost are not a concern at under 20 trainees per cohort. Accessibility needs a basic pass (form labels, contrast, dialog focus). Every `npm audit` finding is in build tooling or unused packages, and `npm audit fix` plus deleting four leftover AI Studio packages clears them all.

## Top 5 quick wins

1. **Close the front door (S1 + S2).** About a dozen lines of rules (require an invite and a verified email) plus swapping the Sign Up tab for an invite message. This removes the two biggest risks.
2. **Two-line rules fixes (S5 + S7).** Stops trainees overwriting each other's progress, and limits which profile fields users can change. Rules and tests only.
3. **Grading-trust fixes (C1 + C2 + C3).** Validate the benchmark input, remove the hard-coded "3.5", and batch the Episode A review writes. Three small, contained changes to things coordinators rely on.
4. **Save & next in the review queue (A1).** Auto-open the next item and add 1–5 keyboard scoring. It's the biggest time saver for instructors and a small change inside `ReviewerQueue.tsx`.
5. **`npm audit fix` + remove the 4 unused packages + add CI (M1 + M2 + M4).** Clears every vulnerability, and makes the existing 65 unit tests and rules tests run on every PR.
